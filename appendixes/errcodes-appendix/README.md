## 附錄 A. PostgreSQL 錯誤碼

<a id="id-1.11.2.2"></a>

PostgreSQL 伺服器
發出的所有訊息都會被指派一個五個字元的錯誤碼，這些錯誤碼遵循 SQL
標準對「SQLSTATE」代碼的慣例。需要知道
發生了哪一種錯誤狀況的應用程式，通常應該
檢查錯誤碼，而不是查看錯誤訊息的
文字。錯誤碼在不同的
PostgreSQL 版本之間較不容易變動，也不會
因為錯誤訊息的在地化而改變。請注意，PostgreSQL
所產生的錯誤碼中，有些（但並非全部）
是由 SQL 標準所定義；另有一些錯誤碼用於
標準未定義的狀況，是自行制定或
借用自其他資料庫。

依據標準，錯誤碼的前兩個字元
表示錯誤的類別，而後三個字元則表示
該類別中的特定狀況。因此，
無法辨識特定錯誤碼的應用程式，仍然可能
從錯誤類別推斷出該如何處理。

[表 A.1](README.md#ERRCODES-TABLE) 列出
PostgreSQL 18.6 中定義的所有錯誤碼。（其中有些目前實際上並未
使用，但由 SQL 標準所定義。）
表中也列出了錯誤類別。每個錯誤類別都有一個
「標準」錯誤碼，其後三個字元為
`000`。此代碼只用於屬於
該類別、但沒有指派任何更特定代碼的錯誤狀況。

「條件名稱」欄中所列的符號，
就是在 PL/pgSQL 中使用的條件名稱。條件
名稱可以用大寫或小寫書寫。（請注意，
PL/pgSQL 不辨識警告（相對於錯誤）的
條件名稱；也就是類別 00、01 與 02 的條件名稱。）

對於某些類型的錯誤，伺服器會回報與該錯誤相關聯的資料庫物件名稱
（資料表、資料表欄位、資料型別或限制條件）；
例如，引發
`unique_violation` 錯誤的唯一限制條件名稱。這類名稱會在
錯誤回報訊息的獨立欄位中提供，因此應用程式不需要嘗試
從訊息中可能已在地化、供人閱讀的文字裡擷取這些名稱。
截至 PostgreSQL 9.3，此功能只有在
SQLSTATE 類別 23（完整性限制條件違規）的錯誤上才完整涵蓋，
但未來很可能會擴大範圍。
